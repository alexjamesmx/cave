# Decisions

Append-only. Newest last. Change a decision by adding a new entry that supersedes it.

| Date | Decision | Why |
|---|---|---|
| 2026-10-12 | Build a custom PWA instead of extending Obsidian for structured records | Obsidian worked for text but was hard to keep up with for money, tasks and habits; a visual, customisable app was wanted |
| 2026-10-12 | Records live in an app database (SQLite on the server, full copy in IndexedDB per device) | Offline writes on the phone and hosting are simple; files-as-database would need the vault on every server |
| 2026-10-12 | Notes stay as Markdown in the Obsidian vault; the app reads them and only creates new files in `Inbox/` | Obsidian is the best editor available; Markdown is what agents read best; LiveSync has rolled back edits to existing files |
| 2026-10-12 | Bun for runtime, package manager, bundler and tests | One tool, already installed, native SQLite; no Node toolchain to maintain |
| 2026-10-12 | Custom per-field last-writer-wins sync instead of a hosted sync engine | One owner and a few devices; Electric and PowerSync need Postgres, LiveStore is pre-v1 |
| 2026-10-12 | Notion-style collections with editable fields and views; Money, Tasks, Journal, Ideas, Wealth, LeetCode, Projects, Reminders are seeded collections | New trackers without code |
| 2026-10-13 | Agents work through an MCP server and HTTP API with per-agent tokens, permissions and an undoable activity log; chat happens in external clients, not inside the app | The app is the memory; Claude, Codex, OpenCode or OpenClaw do the work |
| 2026-10-13 | Model-agnostic: AGENTS.md as the shared rules file, Agent Skills format, a provider adapter for in-app AI | The owner can switch or mix models |
| 2026-10-13 | Visual direction: dark, lime accent, Space Grotesk and JetBrains Mono, command-center home (see `docs/design/`) | Approved mockups |
| 2026-10-12 | M1 tooling: exact-pinned dexie 4.4.6, typescript 7.0.2, @biomejs/biome 2.5.15, @types/bun 1.4.3; `bun.lock` committed; `.gitattributes` forces LF | Reproducible installs; Biome formats LF and the machine has `core.autocrlf` on |
| 2026-10-12 | `fake-indexeddb` 6.2.5 (dev only) runs the Dexie client store under `bun test` | Bun has no IndexedDB; Dexie's docs name it for non-browser runtimes |
| 2026-10-12 | React is added in M2, not M1 | M1 has no UI; no unused dependency |
| 2026-10-12 | HLC: `next()` takes max(wall, last)+counter; `observe()` moves the clock to the max remote stamp seen on every pull; counter overflow past 9999 carries into ms; clock state persists in IndexedDB `meta` | Owner requirement; a device with a slow clock still orders its next edit after what it has seen |
| 2026-10-12 | Equal stamps with different values tie-break on the larger JSON encoding | Only a misbehaving client can cause it, but it keeps merge commutative |
| 2026-10-12 | Sync limits: pull pages of 1000 docs (cursor = last seq sent, client loops until a short page); push at most 1000 docs and 8 MiB per request; client pushes in batches of 200 | Owner requirement for paging; bounded request size |
| 2026-10-12 | `seq` is taken from the `changes` log row (AUTOINCREMENT) inside `.immediate()`, only when the merge changed a key | A doc's seq always equals its newest log row; re-sends do not bump it |
| 2026-10-12 | Server overrides `actor` with `user:<deviceId>`; seed rows use actor `seed` | Clients cannot claim another actor; seed is distinguishable in the activity log |
| 2026-10-12 | `write` view type for the journal's diary editor (accepted in the M1 review) | The plan lists a "write" view but had no type for it |
| 2026-10-12 | Server binds `127.0.0.1` unless `CAVE_HOST` is set, and refuses to start on a non-loopback host without `CAVE_TOKEN`; `JARVIS_TOKEN` renamed to `CAVE_TOKEN` | M1 review item 1 and 6: Bun's default is all interfaces |
| 2026-10-12 | Each local write and pull adopts the clock saved in IndexedDB `meta` inside the same rw transaction before stamping or saving | M1 review item 2: tabs on one device must never issue the same stamp |
| 2026-10-12 | `changes.before` holds `{key: {value, stamp} \| null}` for undo; schema changes go through an append-only migration list keyed on `PRAGMA user_version`; rows from before migration 2 have `before = null` (not recorded); a database newer than the build is refused | M1 review item 3 |
| 2026-10-12 | Sync rejects a request with any stamp more than 10 minutes ahead of server time: 400 `{error: "clock ahead", serverTime}` | M1 review item 4: a fast clock would win every merge and drag all clocks forward |
| 2026-10-12 | An `item` must have a `collection`; `collection` and `setting` docs must have `collection: null` | M1 review item 5 |
| 2026-10-12 | Date values are ISO 8601 local time, `YYYY-MM-DD` or `YYYY-MM-DDTHH:mm[:ss]` when the field has `config.withTime`; a seeded `settings` doc holds `timezone`; `_created` is a UTC ISO string set by the client on a doc's first write; seed icons are Lucide names | M1 review answers to the open questions |
| 2026-10-12 | A `withTime` date field accepts `YYYY-MM-DD` as well as `YYYY-MM-DDTHH:mm[:ss]` | 61 vault ledger entries are date-only; owner approved at M2 planning |
| 2026-10-12 | Field values are checked on every write: `null` clears any field; keys that are not fields pass unchecked; the client refuses the write, the server rejects the sync request (400 naming the field); items of a collection the server has not stored yet are not checked | Outbox order does not promise collections first; unknown keys hold imported extras |
| 2026-10-12 | Importer keeps frontmatter keys that are not fields (journal `source`, `status`, `tags`; LeetCode `confidence`) unchanged in `data` and lists them in the report; ledger `bucket` is dropped as the plan says | Lossless import; owner approved at M2 planning |
| 2026-10-12 | `System/categories.json` only adds category names the seed lacks; its emoji icons are ignored in favour of Lucide names | Seed already has all nine names with Lucide icons; owner approved at M2 planning |
| 2026-10-12 | Frontmatter `created` without a zone is local time in the `settings` timezone, converted to UTC for `_created` | `_created` is UTC by decision; owner approved at M2 planning |
| 2026-10-12 | Clock recovery stores `clockOffset` (server time minus device time) in IndexedDB `meta`; the HLC and `_created` use device time plus that offset from then on. It is only re-measured by another recovery | Resetting the HLC alone does not help while the device clock is still wrong: `next()` takes wall time |
| 2026-10-12 | Each local transaction loads the saved clock (replacing the tab's copy) instead of adopting the later of the two | Every clock change is saved in the transaction that made it, so the saved clock is newest; loading lets a recovery's backwards reset reach every tab |
| 2026-10-12 | `httpTransport(url, now, token?)` throws `ClockAheadError {serverTime, deviceTime}` on 400 `clock ahead` and includes the server's `error` text otherwise | The app shows how far ahead the device is and offers recovery |
| 2026-10-12 | M2 client dependencies, exact pins: react 19.3.0, react-dom 19.3.0, lucide-react 1.48.0; dev @types/react 19.3.0, @types/react-dom 19.3.0. The PWA is served by Bun HTML imports from `Bun.serve` (no Vite); `"/*"` serves it so client routes survive a reload | React was planned for M2; lucide-react is pinned to a release at least two weeks old |
| 2026-10-12 | Icons render from lucide-react's full `icons` map by kebab-case name; unknown names show `circle-question-mark`. Seed icon `home` (an alias missing from the map) is now `house` | Collection and option icons are owner-editable, so the whole set ships in one bundle that works offline |
| 2026-10-12 | Components read IndexedDB through Dexie `liveQuery` wrapped in `useSyncExternalStore` (`web/src/store/live.ts`), not `dexie-react-hooks`; routing is a small history router with one document-level link interceptor | No extra dependency; plain `<a href>` links |
| 2026-10-12 | The server token for a device is entered in Settings and kept in `localStorage` (`cave.token`); the device id is kept there too | Single owner; the loopback default needs no token |
| 2026-10-12 | Fonts load from Google Fonts in `web/index.html`; offline the system fallbacks apply | Bundling font files is deferred to the PWA/service-worker work |
| 2026-10-12 | `GET /api/history/:id` returns one doc's last 200 change-log rows (same bearer rule as sync); migration 3 indexes `changes (id, seq)` | The item drawer shows history from the activity log, which only the server holds |
| 2026-10-12 | Field editor: field ids and select option values are fixed once created; names, icons and colours can change; removing a field keeps item values | Items store ids and values, so renaming them would orphan data |
| 2026-10-12 | Dashboards list entries they cannot count (missing amount, direction, date or value) instead of skipping them | AGENTS.md: money totals include every entry, nothing filtered silently |
| 2026-10-12 | Category and select colours stay the approved design tokens although the dataviz validator fails their lightness band on the dark surface; every coloured mark carries its name as text | Design is approved; CVD separation and contrast pass |
| 2026-10-12 | `url` field values must be `http:`, `https:` or `mailto:` links (validated on write and sync), and the UI renders a link only for those schemes | Security review: a `javascript:` value synced from any device or agent would otherwise become a clickable link |
| 2026-10-12 | Browser checks run with `@playwright/test` 1.63.0 (dev) as `bun run e2e`, specs named `e2e/*.e2e.ts` so `bun test` skips them, against the installed Edge (`channel: "msedge"`, override with `CAVE_E2E_CHANNEL`) and a fresh temp database | No cached Playwright Chromium matched a release at least two weeks old; an installed channel needs no browser download |
| 2026-10-13 | Sync checks only the keys a doc changes (`mergeDoc` against the stored doc). Select membership is checked on device writes and on import only. A field error rejects only that doc: the response lists it in `rejected: [{id, error}]` and the rest of the batch is applied; the client keeps its outbox row and shows the error. Malformed requests and `clock ahead` stay whole-request 400s | M2 review item 1: one stale value blocked a whole batch for good |
| 2026-10-13 | Every sync response carries `serverTime`. Clock recovery sets the offset from the raw device time when the refusal arrived; the offset is deleted after a sync whose raw device time is within 60 s of `serverTime` | M2 review items 3 and 7 |
| 2026-10-13 | Removing a field archives it (`archived: true`, kept in `fields`); field ids are never reused. Views, the drawer, the command bar and validation skip archived fields; the field editor can restore them | M2 review item 2 |
| 2026-10-13 | Seed changes: until the first real database `seed.ts` may change freely. From then on a change to a seeded collection ships as a stamped write with actor `seed`, run at start-up once per `settings.seedVersion`; editing `seed.ts` alone does not reach existing databases | M2 review rule |
| 2026-10-13 | A collection's `fields` array is one key, so two devices editing fields at the same time keep only the later edit; accepted for one owner | M2 review rule |
| 2026-10-13 | The client pushes settings, then collections, then items; `Change` and `Before` live in `shared/types.ts`; `tasks.completed` and `tasks.cancelled` have `withTime` | M2 review items 4, 5, 6 |
| 2026-10-13 | M3 dependencies, exact pins: `@modelcontextprotocol/server` 2.2.0, `zod` 4.6.5, `@fontsource-variable/{space-grotesk,jetbrains-mono,newsreader}` 5.3.0; dev `@modelcontextprotocol/client` 2.2.0 | Newest releases at least two weeks old on 2026-10-13 (SDK 2.3.x and zod 4.6.6+ were too new) |
| 2026-10-13 | Fonts are bundled from Fontsource; Bun's CSS bundler inlines them as data URIs (one 488 KB stylesheet, all subsets), cached by the service worker after the first load | No request leaves the origin; trimming subsets would need hand-written `@font-face` rules |
| 2026-10-13 | Service worker: network first for same-origin GETs outside `/api/` and `/mcp`, one `cave-shell` cache, no precache list. The page warms the cache with what it already loaded once the worker is ready | The first visit loads before the worker controls the page, so runtime caching alone would need a second online visit |
| 2026-10-13 | Bun bundles `<link rel="manifest">` and icon links from `index.html` as hashed assets; `/icons/*` serves the PNGs the manifest names from a fixed list | Bun's HTML bundler resolves those hrefs as files; absolute paths failed to resolve |
| 2026-10-13 | One MCP handler serves every agent: `createMcpHandler((ctx) => buildServer(agentOf(ctx.authInfo), deps))`, with the agent passed in `authInfo.extra` | The SDK hands the factory the request's `authInfo`; one handler per agent is unnecessary |
| 2026-10-13 | `/mcp` accepts `Host` names: loopback, `CAVE_HOST` unless a wildcard, and `CAVE_ALLOWED_HOSTS` (comma list). Origin is checked by hostname only (the SDK helper ignores the port) | Owner decision at M3 planning: agents on Tailscale or the LAN need the machine's name allowed |
| 2026-10-13 | `agent_calls.change_seqs` links each write to its change rows; `GET /api/activity` pages calls by their seq and carries those rows | Owner decision at M3 planning: one cursor cannot page two seq counters |
| 2026-10-13 | The owner API refuses any bearer starting with `cave_`, even when `CAVE_TOKEN` is unset | Agent tokens open `/mcp` only |
| 2026-10-13 | Agent tokens are looked up by their SHA-256 in SQLite rather than compared in constant time | A token holds 256 random bits; a timing difference on its hash reveals nothing usable |
| 2026-10-13 | `add_note` logs the title and body length, not the body | The call log is for seeing what agents did; note text belongs in the vault |
| 2026-10-13 | The manual Claude Code check runs headless (`claude -p --mcp-config`) against a temp database and a copy of the vault; the token stays in a scratch file and an environment variable | Owner decision at M3 planning; `claude mcp add` would store the token in Claude Code's config |
| 2026-10-13 | Agents see collections through one rule, `visibleCollectionDoc`, on every read and write path: live, inside the allowlist, not hidden, not `proposals` | Security review: writes checked only the allowlist and `proposals`, so a future hidden collection would have been writable while invisible to reads |
| 2026-10-13 | One request guard runs first on every `/api/*` route and `/mcp`: `Host` must be in `allowedHosts`; a present `Origin` must equal the server's own origin exactly (scheme, host and port); a `POST` must be `application/json` (else 415). Supersedes the hostname-only Origin check of the earlier `/mcp` entry | M3 review item 1: without it a DNS-rebinding page could read all data through `/api/sync`, and any site could push docs with a no-cors `text/plain` POST |
| 2026-10-13 | Undo syncs and waits first, then plans from the fresh local copy; with no sync it is refused ("Needs a sync first"). Undo writes skip select membership (`LocalStore.write(..., { selectMembership: false })`); type checks still apply | M3 review items 2 and 5: a stale copy would overwrite another device's newer edit; undo should not be stricter than sync |
| 2026-10-13 | The service worker races the network against 3 seconds: on timeout or failure the cache answers; with nothing cached it waits; a late response still refreshes the cache. After warming, the page deletes cached entries it did not load, keeping `/` | M3 review items 3 and 6: offline-first must feel instant on a weak signal, and the cache must not grow per release |
| 2026-10-13 | MCP `update` carries `destructiveHint: true`; `create`, `propose_delete` and `add_note` only add and stay `false` | M3 review item 4 |
| 2026-10-13 | Agents on another machine connect over Tailscale only; on a plain LAN the token would cross the network unencrypted | M3 review item 7 |
| 2026-10-13 | Item titles and bodies written by agents are untrusted: the M4 Markdown renderer emits no raw HTML and links only `isSafeUrl` targets | M3 review item 8 (plan note) |
| 2026-10-13 | Left as is after review: the 488 KB font stylesheet (revisit when a reverse proxy compresses responses), `/c/proposals` reachable by URL, no index on `docs.collection` until `itemsOf` shows in a profile (about 10k docs) | M3 review answers to open questions 1, 4 and 5 |
| 2026-10-13 | Commit messages are one line with no trailers or attribution; PR descriptions carry no footer; merges use `gh pr merge --merge --subject "<one line>" --body ""`. Enforced by `.githooks/commit-msg` (`core.hooksPath`) and `.claude/settings.json` `attribution: { commit: "", pr: "" }`. Commits already on `main` stay as they are | Owner rule at M4 start; pushed history is not rewritten |
| 2026-10-13 | Backups use `VACUUM INTO ?` with the path bound through `db.run`, named `cave-YYYY-MM-DDTHHmm.db` in UTC. A name that exists is refused, never overwritten. A copy counts when `integrity_check` is `ok` and its doc count lies between the source counts read just before and just after the copy | Bun binds the path (checked on 1.4.3); a kept `prepare` statement holds the database open after `close()` on Windows; docs are never removed, so a server writing during the copy only raises the count |
| 2026-10-13 | The server lock is `<dbPath>.lock` (`data/cave.db.lock`), not `data/cave.lock`. The server refuses to start while another live process holds it; `restore` refuses the same way and holds the lock while it works | A test or e2e server on a temp database must not block the real one; the message names the file to delete if a reused PID ever looks alive |
| 2026-10-13 | Restore first checkpoints the current database (`wal_checkpoint(TRUNCATE)`), then renames it and any `-wal`/`-shm` with the same `.before-restore-<UTC time>` suffix | A crash can leave committed pages in `-wal`; renaming only the main file would leave a stale `-wal` beside the restored copy |
| 2026-10-13 | Migration 7 adds `meta(key, value)` with a random `db_id`; restore writes a new one. Sync responses carry `dbId`. A client stores the first one it sees; on a different one it puts every doc in the outbox, resets its cursor to 0 and starts the sync over without applying that page | M4 spec; a device whose first sync after upgrading is also its first after a restore cannot tell, and is left as an open question |
| 2026-10-13 | `bun start` runs `server/main.ts --production`, which passes `development: false` to `Bun.serve`; `bun run dev` passes `true`. No environment syntax in package scripts | Bun's default is `NODE_ENV !== "production"` (measured; not documented); a flag works the same in PowerShell and sh |
| 2026-10-13 | The e2e server runs with `bun --no-env-file` in its own temp folder | Bun loads `.env` by itself; the owner's `VAULT_PATH` or `BACKUP_DIR` must never reach the throwaway database or its backup pruning |
| 2026-10-13 | `/api/status` and `/api/export` sit behind the owner rule. The export holds every doc from the `docs` table in seq order, deleted ones included; no agent tokens, call log or change log | M4 spec |
| 2026-10-13 | The greeting ("Good morning, Alex") sits in the line above "What's the move?", by the hour in the settings timezone: 05–11 morning, 12–17 afternoon, otherwise evening | The approved design keeps "What's the move" as the heading |
| 2026-10-13 | `package.json` carries `"version": "0.1.0-dev"`; `/api/status` reports it | The spec asks for a version and there was none |
| 2026-10-13 | The lock file holds `{ pid, bootAt }` (`bootAt = Date.now() - os.uptime() * 1000`). It is held only by a live PID whose `bootAt` is within 2 minutes of this boot's; an earlier boot's lock, an unreadable one or the old plain-PID format is stale. Locks are created with `wx`; a stale one is removed first, and `EEXIST` means another process won | M4 review item 1: after a crash and reboot a reused PID made the server refuse to start, unattended on the VPS; read-then-write let two processes both take the lock |
| 2026-10-13 | Every `/api` and `/mcp` response, refusals and 404s included, carries `Cache-Control: no-store`, set once in the guard wrapper | M4 review item 3: `/api/export` holds the whole database, and a reverse proxy arrives in M5 |
| 2026-10-13 | Claude Code denies reading `.env`, `.env.local`, `.env.*.local` and `.env.production`; `.env.example` is readable. `attribution.sessionUrl` is `false` | M4 review items 4 and 5 |
| 2026-10-13 | Restore is documented as recovery for a lost or broken server, not a rollback; devices push newer edits back by design. A device whose first M4 sync meets an already-restored server does not rebase; accepted | M4 review item 2 and answer 2 |
| 2026-10-13 | The e2e server also gets `VAULT_PATH`, `BACKUP_DIR`, `CAVE_TOKEN`, `CAVE_HOST` and `CAVE_ALLOWED_HOSTS` set to empty | `--no-env-file` covers `.env` only; with `VAULT_PATH` set in the owner's environment the e2e server imported the real vault into its temp database and two specs failed |
