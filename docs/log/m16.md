# M16 log: reminders only

## Changes

- `shared/lead.ts`: the lead-up (`leadOf`, `leadPoints`, `leadLabel`, `daysUntil`).
- `shared/flows/date-trigger.ts`: `latestArrival` takes a `Lead` and returns the lead-up point; the engine keys a point `flow:<f>:<item>:<date>@<point>` and renders `{{lead}}`.
- `shared/payments-to-reminders.ts`: seed migration 28; `paymentLinkMigration` and `MONEY_PAYMENT_REF` moved here for migration 11. `REPEAT_FIELD` and `TASK_FIELDS` moved to `shared/tasks.ts`.
- Removed: `shared/payments.ts`, `shared/subscriptions.ts`, `mark_paid`, payment notices, the digest's payments, `PaymentForm`, `SubscriptionForm`, `PaymentsView`, `Subscriptions`, `subscription-paid`, `AccountPicker` (only those forms used it), the `payments` view type, `e2e/subscriptions.e2e.ts`.
- The New sheet remounts its form after a save instead of closing; e2e helpers that add one item close it.

## Deviations from the plan

- `shared/lists.ts` keeps `PAYMENT_CATEGORY`/`PAYMENT_ACCOUNT`: seed migration 10 still reads them for a database older than it.
- Migrated reminders carry only the kind as their note, not amount and account (a security review flagged that an agent scoped to reminders but not payments would read them; the owner also wants reminders with nothing else). A payment whose `rem-<id>` is taken is left alone.
- Old Payments and Subscriptions paths open the Agenda, not Transactions: they are reminders now.
- The `mark_paid` MCP test had gone stale with the date (expected `2026-11-22`, got `2026-12-22`); it is deleted with the tool.
